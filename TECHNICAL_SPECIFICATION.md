# Техническая спецификация проекта

## 1. Назначение проекта
Телеграм-бот для помощи жителям республики с правилами дорожного движения. Проект решает проблему недостатка знаний ПДД и предоставляет пользователям быстрые, понятные и безопасные ответы.

## 2. Цель проекта
Создать MVP-решение в виде Telegram-бота, который:
- отвечает на типовые вопросы по ПДД;
- предоставляет краткие и понятные рекомендации;
- в дальнейшем сможет использовать ИИ-агента, работающего на базе документа с правилами ПДД;
- может быть легко масштабирован и развивался далее.

## 3. Основные роли системы
- Пользователь — пишет вопрос в Telegram или выбирает тему из меню.
- Telegram-бот — принимает сообщения, обрабатывает команды и возвращает ответы.
- База знаний — хранит FAQ, темы и контент по ПДД.
- ИИ-агент — в дальнейшем будет использовать документ с ПДД как источник знаний для более гибких ответов.
- Backend — оркестрация логики приложения и взаимодействие с Telegram API, базой данных и ИИ.

## 4. Архитектура решения
### 4.1 Общая схема
1. Пользователь пишет сообщение в Telegram.
2. Telegram отправляет запрос в вебхук бота.
3. Backend получает сообщение и определяет сценарий:
   - простое меню/FAQ;
   - свободный вопрос;
   - запрос к ИИ-агенту.
4. Backend обращается к базе знаний или к ИИ-сервису.
5. Ответ возвращается пользователю через Telegram.

### 4.2 Компоненты
- Telegram Bot API
- Backend на Python
- База знаний в формате JSON/Markdown/SQLite или PostgreSQL
- При необходимости — Supabase как облачная база данных
- Railway как платформа деплоя
- GitHub как система контроля версий и CI/CD

## 5. Рекомендуемый стек
### 5.1 Backend
- Python 3.11+
- FastAPI или Flask
- python-telegram-bot или aiogram
- Pydantic
- Uvicorn

### 5.2 База данных
- На первом этапе: SQLite
- При росте проекта: PostgreSQL через Supabase

### 5.3 Инфраструктура
- GitHub — хранение кода
- Railway — деплой backend и вебхуков
- Supabase — база данных и при необходимости хранение документов/метаданных

### 5.4 Хранилище контента
- JSON/Markdown для FAQ и тем
- Возможность позже перейти на векторную базу знаний для ИИ

## 6. План реализации по этапам
### Этап 1. MVP
Цели:
- создать базового Telegram-бота;
- подключить меню и команды;
- реализовать FAQ по самым частым вопросам ПДД;
- обеспечить простой и понятный UX.

Функции:
- приветствие;
- главное меню;
- темы: знаки, скорость, парковка, перекрёстки, пешеходы, штрафы;
- ответы по часто задаваемым вопросам;
- обработка свободного текста.

### Этап 2. База знаний
Цели:
- структурировать контент;
- хранить ответы в удобном формате;
- сделать систему расширяемой.

Реализация:
- JSON-файлы или база данных с таблицами:
  - topics
  - faq_items
  - answers
  - user_messages

### Этап 3. Интеграция ИИ-агента
Цели:
- сделать бота более гибким;
- дать ответы на основе документа с ПДД.

Подход:
- использовать LLM с RAG-подходом;
- индексировать документ с ПДД;
- передавать пользователю ответ, основанный на retrieved context;
- сохранять верификацию через документы или проверенный контент.

### Этап 4. Масштабирование
Цели:
- повысить надёжность;
- добавить аналитики и логирование;
- подготовить систему к росту пользователей.

## 7. База данных
### 7.1 На первом этапе
Можно использовать SQLite для простоты и быстрого запуска.

### 7.2 При необходимости масштабирования
Использовать PostgreSQL в Supabase.

Рекомендуемые таблицы:
- users
- conversations
- messages
- faq_items
- topics
- feedback

## 8. API и взаимодействие
### 8.1 Telegram
- webhook для получения сообщений;
- обработка команд и кнопок;
- отправка ответов пользователю.

### 8.2 Backend endpoints
- POST /webhook — приём обновлений Telegram;
- GET /health — проверка состояния сервиса;
- POST /admin/faq — добавление или обновление FAQ (в будущем);
- GET /stats — статистика использования (в будущем).

## 9. Безопасность
- хранение токенов в переменных окружения;
- запрещённый доступ к секретам в GitHub;
- использование HTTPS и защищённых webhook-эндпоинтов;
- ограничение доступа к административным функциям.

## 10. Переменные окружения
Необходимые переменные:
- TELEGRAM_BOT_TOKEN
- WEBHOOK_URL
- DATABASE_URL
- SUPABASE_URL
- SUPABASE_KEY
- OPENAI_API_KEY (если будет использоваться LLM)
- APP_ENV

## 11. Развёртывание
### 11.1 GitHub
- репозиторий проекта;
- ветки: main, develop;
- pull request для изменений.

### 11.2 Railway
- деплой backend;
- автоматическое обновление после push в main;
- настройка переменных окружения.

### 11.3 Supabase
- база данных;
- при необходимости хранение расширенной информации и metadata.

## 12. Рекомендации по архитектуре для MVP
Для первого этапа лучше выбрать наиболее простой и быстрый путь:
- Python + FastAPI
- Telegram webhook
- SQLite или Supabase
- JSON/Markdown для контента
- простое меню и FAQ

Это позволит быстро запустить проект, проверить гипотезу и затем перейти к ИИ.

## 13. Рекомендация по дальнейшему развитию
После MVP стоит переходить к:
- более структурированной базе знаний;
- векторному поиску по документам ПДД;
- RAG-архитектуре для ИИ;
- аналитике и улучшению качества ответов.

## 14. Ключевое решение для проекта
Проект лучше строить как гибрид:
- сначала — понятный и быстрый FAQ-бот;
- затем — ИИ-агент поверх базы знаний ПДД.

Это снижает риск, ускоряет запуск и даёт хорошую основу для будущего развития.
